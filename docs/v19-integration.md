## 本轮范围

保留 Figma Make 的显示器透视、地图主题与应用基础。示例选择后直接显示完整方案；弹窗保留「好 / 不要 / 编辑」和关闭按钮。确认后立即显示「已应用」，可撤销、保存。不再有邀请页、假等待或三秒试用倒计时。场景明确包含的延时仍按动作顺序执行，后续指令可取消未完成的动作。

## 示例为什么有不同结果

| 分类 | 演示目的 | 结果 |
| --- | --- | --- |
| 场景建议 | 等人、后排入睡、车外扬尘等当前情境 | 给出相关组合，确认后应用 |
| 直接车控 | 用户明确指定设备或车机已有功能 | 直接处理，信息不足则追问，禁止操作则拒绝 |
| 普通对话 | 拥堵抱怨、纪念日或泛泛疲惫 | 回应，不擅自安排场景 |

目前有 25 个创建案例、7 个建议案例和 11 个分流案例。案例按钮采用独立示例情境；自由输入切换到真实 AI 后调用模型。

「进入录音模式 / 进入露营模式」属于宿主车机入口，Demo 模拟进入对应模式，不生成新场景。录音不启动真实麦克风。原子表中的「进入情景模式」仍为规划中，不能因为车机已有此页面，就把编排调用接口标成已落地。用户要求「创建露营场景」时仍进入编排。

依据另一 session 的 `part1-generation-framework/delivery/` 中结论、结构边界、Prompt 实验报告、接入说明和 manifest，以及 PRD v17。交付源码基线 `c75c5cd`。

该交付包含冻结 p13、实验结果、输入输出契约和离线校验组件；报告明确将完整硬约束链路的服务化接入与端到端验收列为后续工作。按用户要求，本轮不扩建这套架构，也不宣称已完成。

## 冻结配置

- 模型：`deepseek-v4-flash`，官方 `https://api.deepseek.com/chat/completions`。
- `temperature: 0`，`max_tokens: 1000`，`thinking: {type: "disabled"}`。
- `response_format: {type: "json_object"}`，`stream: true`，`stream_options: {include_usage: true}`。
- system Prompt：`lib/prompts/p13-system-zh.md`，不追加其他系统指令。运行时副本在 `lib/data/p13-release.json`。
- SHA-256：`57488940054541ba99365f4e9521391783b42902d468ef68699ae171804d8c12`。
- 用户信封：`{locale, context, utterance}`。中文、英文使用同一 system Prompt。
- 注册表：`2026-09-07.0807`，114 条。逐项核对 id、名称、分组、类别、状态、成熟度、条件/动作值域与禁止值，和交付契约无差异。

`context` 包含停车/行驶状态、当前模拟设备值和启用的档案。未知温度不捏造默认当前值。接口接收 action、none、clarify 等真实模型结果，便于直接测试；不会执行真实车辆动作。

## 续改与应用层边界

为现有编辑功能增加 `partial-revision-v1` 适配器：当前场景放入用户信封 context，要求只返回本次变动，再合并到原场景，并经过已有局部修改检查。冻结的 system Prompt 保持不变。这是新的应用层适配，不继承原实验的成功率结论；批量删除、复杂条件重写仍需手动编辑或补充回归验证。

模型的 `action` 标签本身不会使明确的「创建场景」请求直接执行。宿主界面根据用户指令区分直接控制与待确认提案；服务端返回候选和裁决。情绪描述与明确设备指令并存时，保留明确控制意图。提醒文字作为方案内容标注「待接入」，不混入实际语音回复，也不伪造提醒送达。

模型已拒绝的行人警报关闭请求仍标成「禁止」。模型预先收敛行驶中的灯光/车窗百分比时，若输入有明确设备名称和百分比，保留用户原值、最终值与原因。这是既有裁决的显示修正，不是通用语义解析器。
