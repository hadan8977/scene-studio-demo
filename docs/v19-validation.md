## 真实 API 冒烟

使用工作区已有服务端配置，在本地生产构建上调用 DeepSeek 官方接口。10 次合成输入请求均收到完整 result，模型为 `deepseek-v4-flash`，p13 哈希一致，每次均为 1 次生成。完整耗时约 0.94–1.47 秒；这是该小批样例的实际时延，不是 SLA 或总体性能结论。

| 样例 | 观察 |
| --- | --- |
| 中文等候场景 | 生成灯光与按摩方案，按摩标注规划中 |
| 英文等候场景 | 英文理解与名称，原子字段保持词典中文；音乐标注提议中 |
| 「打开那个」 | 追问目标，不生成动作 |
| 空调 22 度 | 返回 action 和合法车控值 |
| 仅改氛围灯到 10% | 仅此动作变化，原按摩方案与名称保留 |
| 导航剩余距离与灯光颜色 | 不支持的触发条件阻止保存，颜色单独记录 |
| 关闭行人警报音 | 无可执行动作，要求澄清；首次暴露裁决标签问题 |
| 行驶中车窗与灯光 100% | 输出安全范围；首次暴露模型先调值后原值丢失的问题 |
| 行人警报复测 | 修复后分类为 forbidden，禁止保存 |
| 行驶限制复测 | 车窗 100%→20%、灯光 100%→50%，原值和理由齐全 |

[合成输入与接口返回记录](v19-live-smoke.json)包含初测和复测，保留发现的问题，不将全部响应描述为一次性完美通过。没有调用私有评测题集，也没有重新运行报告的全量模型试验。提示词质量、复杂续改和完整硬约束架构不在本次冒烟验收结论内。
