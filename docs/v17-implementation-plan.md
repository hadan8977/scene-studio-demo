## 2 阅读比例

保留 Figma 原稿风格，调整实际尺寸而非仅用网页整体放大：正文 22–24px，辅助说明约 18px，标题 34–40px；主按钮高至少 56px；侧栏约 320px，场景列表两列；完整提案宽约 700px，操作区固定、正文内部滚动。屏幕仍为 1920×1080，减少外部无效留白，增加可选择的正视阅读模式。复杂场景通过分组与渐进展开控制密度。

验收：场景名、理解句、取值和三种决策在常见桌面窗口可辨认；不以缩小文字修补溢出；长中文、英文、规划说明可以换行；焦点、触摸目标与弹层滚动保持正常。

## 3 地图对齐

车辆、地点与路线分开建模。静态路线选自真实龙腾大道的连续道路几何，车辆位置从路线上插值，朝向由局部切线计算；地点保持真实坐标并使用不同符号。所有地理元素进入同一 SVG viewBox，在外层统一缩放与透视，禁止额外百分比定位覆盖车辆。

验收：车辆点到路线距离近于零；不同窗口尺寸和阅读视角下仍重合；静态路线和车辆模拟属性明确；现有炭黑/青柠风格及 OSM 署名保留。

## 4 输入与路由

| 输入                        | 路径           | 用户看到的结果                                   |
| --------------------------- | -------------- | ------------------------------------------------ |
| 把灯调暗、温度24度          | 车控直达       | 短反馈与模拟车况变化，无场景生成、无保存卡       |
| 热死了 / 冷死了             | 车控           | 单项舒适调控反馈，不扩大为组合场景               |
| 进入露营模式                | 官方预设       | 调用预设的模拟反馈，不重新拼一个场景             |
| 她说还要二十分钟            | 处境旁路       | 先回应，再轻问一句；同意后应用一次，保存另作决定 |
| 今天心情不好 / 今天是纪念日 | 闲聊           | 不主动营造气氛、不自动写记忆                     |
| 又堵了，烦死了              | 闲聊           | 车改善不了堵车，不发场景建议                     |
| 开车有点困                  | 回应与停车提醒 | 不生成放松、按摩或助眠场景                       |
| 帮我把那个打开              | 追问           | 先明确对象；答复后转相应车控                     |
| 做一个雨夜回家的场景        | 显式场景创建   | 理解句、条件、组合动作、校验、修改与保存         |
| 提案编辑态中的灯再暗一点    | 当前场景续改   | 只改这一项，其他内容保留                         |

路由与预置案例均为明确标注的 demo 规则，不宣称已有通用 NLU、实车控制或自动学习。真实模式继续走同站服务端并保留不支持与错误反馈。

## 5 主动流程

1. 状态表达先回应；处境、情绪、生理状态分开处理。
2. 优先查已有场景；没有匹配时生成候选。
3. 依次检查可改善性、车况、负面偏好、打扰状态与实际变化。组合建议通常至少涉及两个元素；停车疲劳提示官方休憩模式按 v17 的单独分支处理。
4. 首次低打扰询问；拒绝保留冷却记录，评审可以查看裁决与重置独立演示。
5. 同意不自动保存。三秒预览只模拟可用的灯光和声音，然后应用一次可用动作；规划/提议能力继续标注，不假装执行。
6. 可还原；后续车控指令优先，不被旧预览定时器或还原操作覆盖。
7. 行驶中需完整查看的建议进入“它的想法”；停车后打开、裁剪、保存或丢弃。

## 6 案例覆盖

至少覆盖 20 个正例与反例，主动处境和显式创建分开呈现。分类包括等人与休息、后排安静、空气与日晒、长途、定时通勤、冬季加热、周末屏幕、阅读与会前准备、露营娱乐、停车视频、明确庆祝、原有场景复用。

组合按目的选能力，不为凑数堆动作。注册表已有、无 UX、排期、待定和提议严格按成熟度标注；同一概念方案按既有约束最多包含一项未落地动作。日期范围、歌名等参数按格式校验；“导航剩余距离”“氛围灯颜色”等删除或不存在的能力必须有清楚的失败说明。

## 7 场景应用与管理

新增“它的想法”，保留“我的场景”“它学会了什么”。案例带用途、原句与代表性能力；取消含糊的能力边界入口。动作分组使用灯光、声音、空气与香氛、温度与座椅、车窗与门、播报与出口；预设与延时独立作为基础和时序提示。

保存前对条件与动作相似度进行本地比较。已有条目编辑直接更新；新提案命中相似条目时显示差异并提供更新已有、另存与取消。所有持久化都在当前浏览器，恢复旧版本场景不自动执行。

## 8 验证与交付

- 数据：逐一验证预置组合，覆盖新增原子能力与成熟度；不含删除字段，不保存占位参数或禁止动作。
- 规则：车控/预设/闲聊/追问/主动/显式/续改路径；拒绝、负面偏好、行驶、不支持和重复场景。
- 状态：三秒预览、取消、还原、后续车控优先、并发提交、存档刷新、丢弃、收件箱与查重。
- 显示：字号与控件目标、完整提案溢出、地图共用坐标系、两种屏幕视角；浏览器环境可用时补截图检查，不用 DOM 测试冒充实车视觉验收。
- 工程：针对性测试、类型检查、生产构建、公开部署资源和 API 状态检查。
- 交付：新版主链接、旧版备份链接、公开仓库、计划完成情况与验证记录。真实模型质量和时延仍需有效 OpenRouter 密钥联调。
