# LUMA · 场景应用与生成卡片

本轮重做以第一部分的一句话生成流程为核心。生成结果是一个有名字、可理解、可修改、可保存的场景，界面不能退化为设备功能目录。

## 产品结构

- **车机系统**：1920 × 1080 固定设计画布，外层金属边框与玻璃表面只负责呈现设备质感。浏览器按可用空间等比例缩放，并通过 2° 水平轴和 -5° 垂直轴旋转模拟驾驶员视角。所有操作、编辑、设置、确认与反馈均在屏内。
- **座舱上下文**：导航与音乐作为演示应用，系统栏和应用切换始终保留。它们是场景卡存在的环境，不具备真实导航、媒体或车辆控制能力。
- **生成卡片**：单张 660px 宽浮层，约占屏宽34%。默认停靠于应用右下方，保留地图和导航指引。光、声、气、温、话、供是内部信息分组，使用图标、数值和细分隔线，不再拆成独立卡片。空分组不出现。
- **场景应用**：我的场景、灵感场景、创建、详情与编辑，以及“它学会了什么”。列表可以搜索、重新打开和删除。模板与用户保存的内容明确区分。

## 核心流程

1. 用户从应用里说写一句，或查看导航上的演示提案。
2. 理解句先出现；校验后展示条件和动作。等待反馈保留原话，不用假动画冒充实测时延。
3. 点击“改一下”进入当前卡片的编辑状态。再次表达仅修改涉及的项目，也可点值调整、改名、增删动作与条件。参数仍受同一注册表与验证器约束。
4. 点击“就这样保存”后进入“我的场景”列表。更新已有场景沿用同一 ID，不复制为多条。保存不代表立即应用。
5. “不用”丢弃草稿；右上角收起只隐藏卡片，保留草稿。两者不同。
6. 缺信息就在同一卡片内追问；行驶态只保留三行摘要并暂停编辑与新建，停车后可继续。

不支持和禁止项灰显并带原因；调整保留原值、最终值和理由；规划中、提议中分别标注。使用的记忆可逐条停用，并在档案页恢复；偏好分别按林/周档案保存在当前浏览器。模型、真实时延、车况模拟和逐项裁决收进屏内设置面板。

浮层是第一部分生成结果的呈现演示，不代表已实现第二部分的状态旁路、门控、打扰额度、信任升级、观察学习或自动执行。没有演示中自动执行三秒试演或倒计时执行。

## 设计主题

**微光 / Quiet Signal**：以用户提供的 Figma Make「Card Stack」为主要设计参考，采用近黑 #0b0c0e、炭灰 #15171a、黄绿 #cdec52。细边界与宽柔阴影区分屏幕、应用和单张服务提案；应用文字、图标、按钮与卡片共用同一套颜色语义。Hanken Grotesk 与 DM Mono 字体随应用自托管，中文使用系统字体。

原创四向汇聚星形 logo 对应“多个动作汇成一个场景”，右上小点代表当下。卡片在 520ms 内从底部轻微回弹进入，240ms 收起；生成时使用环形微光呼吸，数值变化只强调被改动的行。支持减少动态效果偏好。退出期间内容保持原样、移出键盘交互，重新打开会取消退出计时。

每个动作是一行设置，图标标识分组、细刻度辅助读取，避免把每个设备拆成卡片。主卡正文约 17–19px，标题 34px，主按钮 56px（1920 设计画布）。场景管理以完整场景为单位陈列；档案以偏好列表呈现，负面偏好使用柔和珊瑚色。

这些是桌面概念演示尺寸，尚未进行真实显示器观看距离或实车人体工学验证。

### 档案与“它学会了什么”

无档案、林、周可直接在应用侧栏切换。每个演示档案有四条独立偏好，可以“拿走”或恢复。删除一条温度偏好不会连带删除灯光或空气净化偏好。修改只影响后续生成，已保存场景保留原设置；保存时记录采用的档案。

界面明确说明这是预置演示偏好，尚未接入观察学习。当前档案及逐条停用状态分别存储，不把本地偏好管理包装成第二部分的自动学习能力。

所有界面图形均为本项目代码绘制。没有复制品牌标识、概念车截图或设计师素材作为产品资产。
