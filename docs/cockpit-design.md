# LUMA · 场景应用与生成卡片

本轮重做以第一部分的一句话生成流程为核心。生成结果是一个有名字、可理解、可修改、可保存的场景，界面不能退化为设备功能目录。

## 产品结构

- **车机系统**：1920 × 1080 固定设计画布，外层金属边框与玻璃表面只负责呈现设备质感。浏览器按可用空间等比例缩放。所有操作、编辑、设置、确认与反馈均在屏内。
- **座舱上下文**：导航与音乐作为演示应用，系统栏和应用切换始终保留。它们是场景卡存在的环境，不具备真实导航、媒体或车辆控制能力。
- **生成卡片**：单张 752px 宽浮层，约占屏宽39%。默认停靠于应用右下方，保留地图和导航指引。光、声、气、温、话、供是内部信息分组，使用图标、数值和细分隔线，不再拆成独立卡片。空分组不出现。
- **场景应用**：我的场景、灵感场景、创建、详情与编辑。列表可以搜索、重新打开和删除。模板与用户保存的内容明确区分。

## 核心流程

1. 用户从应用里说写一句，或查看导航上的演示提案。
2. 理解句先出现；校验后展示条件和动作。等待反馈保留原话，不用假动画冒充实测时延。
3. 点击“改一下”进入当前卡片的编辑状态。再次表达仅修改涉及的项目，也可点值调整、改名、增删动作与条件。参数仍受同一注册表与验证器约束。
4. 点击“就这样保存”后进入“我的场景”列表。更新已有场景沿用同一 ID，不复制为多条。保存不代表立即应用。
5. “不用”丢弃草稿；右上角收起只隐藏卡片，保留草稿。两者不同。
6. 缺信息就在同一卡片内追问；行驶态只保留三行摘要并暂停编辑与新建，停车后可继续。

不支持和禁止项灰显并带原因；调整保留原值、最终值和理由；规划中、提议中分别标注。使用的记忆可移除。模型、真实时延、车况模拟和逐项裁决收进屏内设置面板。

浮层是第一部分生成结果的呈现演示，不代表已实现第二部分的状态旁路、门控、打扰额度、信任升级、观察学习或自动执行。没有演示中自动执行三秒试演或倒计时执行。

## 设计主题

**光学玻璃与暮色座舱**：底层使用蓝灰色夜间环境；单张提案使用有厚度的冷白玻璃表面，蓝色为确认和编辑的操作色，浅黄绿色只点缀系统状态。空间层级由明暗、边缘反射和阴影共同建立，不通过大量装饰容器堆叠。

界面以原生1920画布下约22–25px的主要正文、60–70px主操作为基准。设备的真实物理尺寸与观看距离尚未给定，因此不宣称已完成毫米尺度或真实车辆驾驶安全验收。
